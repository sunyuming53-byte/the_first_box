# D-AIS48025A 技术文档

## 1. 文档目的

本文档用于汇总 `D-AIS48025A` 低压智能伺服驱动器在本项目中的已知技术信息，方便后续开发、联调、排障与 issue 回溯。

本文重点覆盖：

1. 驱动器基本规格与接口
2. 接线信息
3. Modbus RTU 通信参数
4. 关键寄存器清单
5. 速度模式、位置模式、脉冲模式下的指令语义
6. 当前代码实现与硬件实测结论
7. 已知不确定项与后续建议

> 重要原则：
> - **硬件实测优先于 issue 初始假设**
> - **代码现状不等于手册真相**
> - **本文明确区分“已验证”“手册记录”“尚存疑”**

## 3. 驱动器概览

### 3.1 型号定位

- 型号：`D-AIS48025A`
- 类型：低压智能伺服驱动器 / 一体式低压直流伺服
- 调试软件：`AIMOTOR`
- 通信接口：`RS485 (Modbus-RTU)`，并带 CAN 相关预留

### 3.2 已知规格

| 项目 | 数值 / 说明 |
|------|-------------|
| 输入电压 | `DC 24~60V` |
| 额定电流 | `25A` |
| 电机额定转矩 | 项目内寄存器文档按 `1.27Nm` 使用 |
| 额定转速 | 项目内寄存器文档按 `3000rpm` 使用 |
| 脉冲接口电压 | `5~24V` |
| 最大脉冲频率 | `200kHz` |
| 控制模式 | 位置 / 速度 / 转矩 / 通信 |

> 注：某些规格来自项目内整理文档，不代表已全部逐项硬件复核。

## 4. 接口与接线

## 4.1 CN1：电源与电机动力

| 引脚 | 含义 | 说明 |
|------|------|------|
| `DC+` | 电源正 | `24~60V` 直流输入 |
| `DC-` | 电源负 | 电源地 |
| `U` | 电机 U 相 | 三相输出 |
| `V` | 电机 V 相 | 三相输出 |
| `W` | 电机 W 相 | 三相输出 |

### 接线要点

1. 电源正负极不可反接
2. 推荐电源容量至少大于额定需求，知识库建议 `>= 1.5 倍额定电流`
3. 动力线与信号线尽量分开布线

---

## 4.2 CN2：编码器接口

| 引脚 | 含义 | 说明 |
|------|------|------|
| `5V` | 编码器供电+ | 驱动器提供 |
| `0V` | 编码器供电- | GND |
| `SD+` | 串行数据+ | 差分信号 |
| `SD-` | 串行数据- | 差分信号 |
| `PE` | 保护地 | 外壳屏蔽接地 |

### 接线要点

1. 编码器线建议使用屏蔽线
2. 屏蔽层和 PE 处理要一致，避免干扰导致编码器异常

---

## 4.3 CN3：I/O 接口

| 引脚 | 默认功能 | 说明 |
|------|----------|------|
| `DI1` | 使能 | **非常关键**，不满足使能条件时 `H32_02` 不会到 5 |
| `DI2` | 复位 | 在项目位置模式中被重映射为多段触发 |
| `DI3` | 急停 | 默认 EMG |
| `DI4` | JOG+ | 正向点动 |
| `DI5` | JOG- | 反向点动 |
| `DO1` | READY | 就绪输出 |
| `DO2` | ALARM | 报警输出 |
| `DO3` | INPOS | 定位完成输出 |
| `DI-COM` | DI 公共端 | 支持 NPN/PNP |
| `DO-COM` | DO 公共端 | 支持 NPN/PNP |

### 与本项目相关的关键事实

1. `DI1` 必须满足驱动器使能硬件条件，否则软件写 `H32_01=1` 也无法真正进入使能态
2. 在通信位置模式下，项目会把 `DI2` 改映射为：

```text
H03_04 = 28   # DI2 -> FunIN.28 PosInSen
H03_05 0->1   # 作为多段位置启动边沿
```

也就是说：

- 默认手册中的 `DI2=复位`
- 在本项目位置模式配置后，`DI2` 的语义已被软件重绑定

---

## 4.4 CN5：脉冲输入接口

| 引脚 | 含义 | 说明 |
|------|------|------|
| `PUL+` | 脉冲正 | 差分脉冲 |
| `PUL-` | 脉冲负 | 差分脉冲 |
| `DIR+` | 方向正 | 方向信号 |
| `DIR-` | 方向负 | 方向信号 |

### 脉冲接口说明

知识库记录：

- 支持 `脉冲 + 方向`
- 支持 `CW + CCW 双脉冲`
- 最大脉冲频率 `200kHz`

### 当前项目状态

项目当前主要使用 **Modbus 通信控制**，并没有在 C++ 驱动里实现对外部硬件脉冲输入的完整接入与验证。

因此：

- CN5 脉冲接口是驱动器原生能力
- 但当前项目 `dais_motor` 主要走的是 **RS485 通信命令链路**

---

## 4.5 CN7 / CN8：RS485 通信

| 引脚 | 含义 |
|------|------|
| `485A` | RS485 A / T+ |
| `485B` | RS485 B / T- |
| `GND` | 通信地 |

### 接线建议

1. 使用 USB 转 RS485 适配器时，保持 A/B 极性一致
2. 多驱动器组网时，在总线末端加 `120Ω` 终端电阻
3. 通信线使用双绞屏蔽线，避免与强电共槽

### 32 位寄存器字序

```text
H0C_26 = 1

```

- `H05_07`
- `H05_09`
- `H11_12`
- `H0B_07`
- `H0B_15`

## 6. 地址计算规则

寄存器命名形如 `HGG_NN`：

```text
十六进制地址 = 0xGGNN
十进制地址   = GG(hex) * 256 + NN(dec)
```

例如：

```text
H02_00 -> 0x0200 -> 512
H06_03 -> 0x0603 -> 1539
H0B_07 -> 0x0B07 -> 2823
```

## 8. 速度模式、位置模式、脉冲模式的指令语义

这是后续最容易混淆的部分，单独展开。

## 8.1 速度模式

### 生效条件

```text
H02_00 = 0
H06_02 = 0
```

### 目标指令寄存器

```text
H06_03   # Int16, rpm
```

### 当前代码语义

`dais::Motor::set_velocity_command(double rad_per_s)` 最终会换算为：

```text
rpm = rad_per_s * 60 / (2π)
写入 H06_03
```

### 反馈寄存器

| 寄存器 | 含义 |
|--------|------|
| `H0B_00` | 实际转速 rpm |
| `H0B_02` | 实际扭矩/内部扭矩命令 |
| `H0B_07` | 真实位置 |

### 已验证结论

1. `H06_03` 在速度模式下工作正常
2. 速度斜坡测试 `60 -> 150 -> 300 -> 600 -> 200 -> 0 rpm` 已通过

---

## 8.2 通信位置模式

这是项目目前最重要的一条新结论。

### 先说结论

**位置模式不是把 H06_03 当位置目标。**

已实测确认的通信位置链路是：

```text
H02_00 = 1          # 位置模式
H05_00 = 2          # 位置指令源 = 内部多段(H11)
H11_04 = 1          # 绝对模式
H11_12 = 目标位置   # Int32, instr. units
H03_04 = 28         # DI2 -> PosInSen
H03_05 0->1         # 触发单次运行
```

### 关键纠偏

早期 issue 曾假设：

```text
H02_00=1 后，H06_03 变成位置目标
```

这个假设已被 `probe_position_mode.py` **证伪**：

- 向 `H06_03` 做 FC10 Int32 写入
- 电机不动
- `H0B_07` 不跟随变化

因此后续严禁再把 `H06_03` 当位置目标。

### H11 路径的含义

| 寄存器 | 含义 |
|--------|------|
| `H11_00` | 运行模式，项目中使用单段运行 |
| `H11_01` | 结束段号 |
| `H11_04` | 位移类型，`1=绝对` |
| `H11_12` | 段 1 位置目标 |
| `H11_14` | 段 1 最高转速 |
| `H11_15` | 段 1 加减速时间 |

### 位置单位与换算

项目当前使用：

```text
H05_07 = 131072   # 编码器分辨率
H05_09 = 1000     # 齿轮比分母 / 指令单位每转
```

因此项目内将 `H11_12` / `H0B_07` 解释为：

```text
1000 instr. units = 1 rev
position_rad = counts * 2π / 1000
```

即：

```text
counts = round(rad * 1000 / (2π))
```

### 触发机制

位置目标写入后不会自动立刻跑，还需要触发：

```text
H03_05: 0 -> 1
```

项目实测发现：

- 若边沿过短，连续第二次位置命令可能不动作
- 现实现中在触发前会先拉低约 `50ms`，再拉高

即：

```text
0 -> 等 50ms -> 1
```

这是当前连续步进稳定工作的关键。

### 当前 C++ API 语义

位置模式下：

```cpp
dais::MotorConfig cfg;
cfg.control_mode = dais::ControlMode::Position;
motor.configure_device();
motor.enable();
motor.set_position_command(target_rad);
```

`set_position_command()` 表示：

- **绝对位置**，单位为 `rad`
- 内部转换成 `H11_12` 的 Int32 目标

### 已验证结论

1. `+0.5rad`
2. `+1.0rad`
3. 回原点

都已通过 `motor_hw_test --mode position` 验收。

## 8.3 脉冲模式

### 已知事实

驱动器原生支持外部脉冲控制：

- `脉冲 + 方向`
- `CW + CCW`

并且位置指令源存在：

```text
H05_00 = 0   # pulse
```

### 但当前项目未完成的部分

项目目前没有在 `dais_motor` 中建立“外部脉冲输入模式”的完整验收链，因此下面几件事**不能写成已验证结论**：

1. 外部脉冲输入的实际电子齿轮换算
2. 脉冲数与 `H0B_07` 的精确对应关系
3. PUL/DIR 与 CW/CCW 两种硬件模式的实测差异

### 目前能写出的可靠结论

在驱动器层面：

```text
H05_00 = 0
表示位置指令源来自脉冲输入，而不是内部多段(H11)
```

结合项目设置 `H05_07=131072`、`H05_09=1000`，通常可以推断：

```text
1 rev = 1000 指令单位
```

但“外部输入脉冲数是否严格等于这 1000 指令单位”这一点，**需要独立硬件验证**，当前不能当成已证明事实。

### 对未来的建议

若后续要正式支持脉冲模式，建议单独做以下探测：

1. 固定 `H05_07=131072, H05_09=1000`
2. 输入已知脉冲数（如 100 / 500 / 1000）
3. 记录 `H0B_07` 实际变化
4. 建立“脉冲数 -> 指令单位 -> rad”的实测映射

## 11. 关键行为与项目结论

## 11.1 Issue #63 结论

1. `position_rad` 过去读错了 `H0B_13`
2. 现在已改为 `H0B_07`
3. `H0B_15` 已接入为 `position_error_rad`
4. 通信位置模式已实现，并走 `H11_12`

## 11.2 Issue #64 结论

1. 已补齐 32 位写能力（FC10）
2. `configure_device()` 已显式写 `H02_00`
3. `enable()` 与 `configure_device()` 已解耦

## 11.3 Issue #65 结论

1. 故障码不再只是打印日志
2. 读到故障会触发：
   - 命令清零
   - 错误锁存
   - 自动失能
3. 上层 `DaisHardware` 也会停止继续写命令

## 13. 已知不确定项

以下内容不能视为最终定论：

## 13.1 H0B_24 相位电流位宽

当前结论：

1. 原实现把它按 `uint16 * 0.01A` 解析，会在失能时出现 `655A` 一类假值
2. 现已先修正为 **signed Int16 × 0.01A**
3. 但它是否实际上应读成 **Int32**，当前证据不足

原因：

- 项目内 `register_map.md` 写它是 Int32
- 但现有 PDF/知识库并不能可靠复核这一点
- 硬件上也尚未做 “1 寄存器 vs 2 寄存器” 的严格对照实验

所以当前最稳妥说法是：

```text
H0B_24 符号问题已修正；
位宽问题仍待硬件确认。
```

## 15. 最终总结

对本项目而言，D-AIS48025A 当前最重要的工程结论是：

1. **速度模式命令寄存器是 `H06_03`**
2. **真实位置反馈寄存器是 `H0B_07`，不是 `H0B_13`**
3. **通信位置模式真实目标寄存器是 `H11_12`，不是 `H06_03`**
4. **位置模式需要 `H05_00=2 + H11_12 + H03_05 触发`**
5. **DI1 是使能硬条件，DI2 在本项目位置模式里会被重映射**
6. **故障码现在必须被当作保护事件处理，不能只打印日志**
7. **H0B_24 电流寄存器的符号问题已修，但位宽仍需后续实验定案**

如果未来只看一页结论，优先记住这三句：

```text
速度命令 -> H06_03
真实位置 -> H0B_07
通信位置目标 -> H11_12（不是 H06_03）
```
